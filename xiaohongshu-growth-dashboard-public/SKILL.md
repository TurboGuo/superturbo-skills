# 小红书涨粉诊断看板

把小红书后台导出变成一个可以直接打开的中文诊断看板。核心不是画图，是**把「为什么不涨粉」定位到具体环节，并给出能立刻执行的动作**。

## 这个看板的骨架

一条恒等式撑起全部：

```
粉丝转化率 = 标题封面吸引力 × 内容吸引力
涨粉/曝光 = (观看/曝光) × (涨粉/观看)
```

前半段负责骗到点击，后半段负责让人愿意关注。三个数字都换算成百分制并分成良好、中等、较弱三档，用户一眼就能看出问题出在哪一段。详见 `references/scoring.md`。

## 铁律

**`assets/template.html` 一个字都不要改。** 全部 CSS、布局、配色、明暗、交互、各卡片的小标题和说明句都在里面写死，这是每次输出都一模一样的原因。你只提供数据和文字。

**页脚由 `prepare.py` 自动生成**，不要重写。只有一种情况可以追加：有数据缺口要说明，键名用 `数据缺口。`，加在末尾。

**封面示意从 `assets/snippets.md` 复制**，不要自己写 HTML，类名和嵌套结构错了就渲染不出来。

**自由文本按 `references/format-contract.md` 写。** 那里规定了数字精度、千分位、`保持：`/`修改：` 前缀、依据句式、bullet 条数上限。

`assets/demo/` 是一套完整的参照输出（示例导出 + 三个 json + 渲染好的 dashboard.html）。**动手前先打开 `assets/demo/dashboard.html` 看一眼成品长什么样**，你的产出应当与它逐处对应，只有数据和文字不同。

## 流程

严格按顺序，第 3 步不能跳过。

### 1. 收集输入

拿到导出表有两条路，从省事的往下走，第一条能拿到就不用往下：

**A. 用户直接给文件**（默认，零配置）

请用户从创作者中心 → 数据中心 → 笔记数据 → 导出，拿「笔记列表明细表」。
`.xlsx` 和另存的 `.csv` 都能读。

**B. 让脚本去文件夹里找**

用户说「文件在某个文件夹里」时，别让他重新导一次：

```bash
python3 scripts/discover.py <文件夹>
```

按表头内容认文件，不认文件名，改过名和下载了好几份都能找出来，
顺带把可能的封面图目录一起报出来，最后打印下一步该跑的命令。

必须拿到：

- **笔记列表明细表**（见上面 A 或 B）
- **今天的真实粉丝总数**。导出表里没有这个数，必须问用户，否则粉丝曲线无法锚定。
- **时间范围**。默认最近 14 天。不足 8 篇笔记就建议放宽到 30 天，并告诉用户原因。

尽量拿到，没有也能做：

- **封面图**。有图才能做真正的封面分析，没有就只能用点击率反推，要在看板里注明。
- **正文**。用于判断结构问题。
- 主页截图和简介，用于判断关注转化。

一次性问齐，不要挤牙膏。

### 2. 算指标

```bash
python3 scripts/prepare.py 笔记列表明细表.xlsx \
  --followers <粉丝总数> --start <YYYY-MM-DD> --end <YYYY-MM-DD> \
  --out metrics.json
```

脚本会打印恒等式验算，对不上就停下来查数据。它会自动剔除标题为空的笔记（这类无法定位到具体内容），数量记在 `meta.dropped` 里，要写进页脚。

**列是按表头名取的，不是按位置。** 小红书改过导出表的列顺序，写死下标读错列
不会报错、结果看起来还很正常，是最难发现的一类错。如果启动时打印了「导出表里
没有这些列」，把缺的列记下来，缺的字段按 0 算，相关诊断不要写。表头名又变了就
往 `prepare.py` 的 `ALIASES` 里加别名。

每篇还会算出 **CES**（`ces`）和千曝光效率（`cesK`），公式见
`references/algorithm.md`。`cesK` 用来把小而精的笔记和大而空的爆款放在一起比。

读一遍 `references/algorithm.md`，对照四道闸门判断每篇死在第几关。

### 3. 搜索最新的博主经验（必做）

`references/practitioner.md` 是基线，但平台打法几个月就变一次。**每次生成看板前必须真的搜一轮**，至少覆盖：

1. `小红书涨粉实操复盘 <当前年份>`
2. `小红书封面点击率 提升 实测`
3. `小红书 转粉率 低 怎么办 主页`
4. `小红书算法 更新 <当前年份>`

如果用户的账号有明确垂类（美妆、留学、健身……），再补一条该垂类的搜索。

搜到的结论与基线冲突时以新的为准，并在页脚注明。**只引用真实搜到的或基线文件里有的内容，不要编造博主案例和数字。**

### 4. 看封面

如果拿到了封面图，逐张看，记录：比例、大字是否可读、大字是否压在密集内容或深色区、主视觉是中文还是英文、风格是否统一。把每张的一句话描述写进 `metrics.json` 对应笔记的 `coverDesc`，并把 `coverKey` 设成封面文件名（不含扩展名）。

比例和点击率的关系通常很明显，值得单独算一下：把 3:4 附近的和横图的平均点击率分开对比。

### 5. 写逐篇诊断

按 `references/writing-guide.md` 的规范，为每篇笔记写 9 个格子，输出 `analysis.json`：

```json
{
  "笔记标题必须和导出表完全一致": {
    "fanAlgo": ["粉丝转化率 · 算法视角，1 到 3 条"],
    "fanBlog": ["粉丝转化率 · 博主视角"],
    "fanFix":  ["综合建议，以 保持： 或 修改： 开头"],
    "covAlgo": [], "covBlog": [], "covFix": [],
    "conAlgo": [], "conBlog": [], "conFix": []
  }
}
```

每条 bullet 必须带真实数字或具体动作。两个视角要真的不同，说同一件事就是没写好。

### 6. 写总建议

3 到 5 条，输出 `suggestions.json`：

```json
[{
  "h": "标题是一个可直接执行的动作，不是一个观察",
  "t": "触发它的看板数字，关键值用 <b> 加粗",
  "p": ["2 到 4 条具体做法"],
  "s": "算法依据：…… 实操依据：<a href=\"…\">来源</a> ……",
  "demo": "可选，封面示意 HTML"
}]
```

按杠杆排序。没有可操作动作的条目直接删掉，脚本会强制校验条数。

### 7. 渲染

先照着 `assets/demo/` 里的三个 json 核对一遍自己的字段格式，再渲染。

```bash
python3 scripts/render.py --metrics metrics.json --analysis analysis.json \
  --suggestions suggestions.json --covers covers/ --out dashboard.html
```

封面放 `covers/<coverKey>.jpg`，脚本会缩略并内联成 data URL，输出始终是单文件。

页脚已由 `prepare.py` 生成好，不用写。只有一种情况需要动 `meta.footnotes`：有数据缺口要说明（例如只拿到部分封面、某几篇观看量过低），追加一条在末尾，键名用 `数据缺口。`。

### 8. 自检后再交付

先跑机械检查：

```bash
python3 scripts/verify.py dashboard.html
```

它会验区块是否齐全、恒等式、分档与分数是否一致、建议条数与字段、九个诊断字段、`保持：`/`修改：` 前缀、bullet 条数、页脚六条。**有 FAIL 就不要交付。**

脚本查不了的，人工过一遍：

- [ ] 和 `assets/demo/dashboard.html` 并排看一眼，版式没有跑偏
- [ ] 每条 bullet 都有真实数字或具体动作，没有空话
- [ ] 算法视角和博主视角说的不是同一件事
- [ ] 引用的每个外部数字都能追到来源，没有编造的案例
- [ ] 浏览器里切过四个标签、点过排序、试过深色模式

## 看板长什么样

```
标题 + 两条依据说明（算法侧 / 博主侧）
┌──────────────┬──────────────┐
│ 绝对涨粉量    │ 粉丝转化率 /100 │
├──────────────┼──────────────┤
│ 标题封面 /100 │ 内容吸引力 /100 │
└──────────────┴──────────────┘
总粉丝与每篇表现（粗线粉丝总数 + 三格细线：涨粉量、三项得分，共用日期轴）
逐篇分析（涨粉总览可排序 + 三个分维度标签，全部直接展开）
总建议 3 到 5 条
页脚
```

明暗两套配色，悬浮提示，表格视图。

## 反复出问题的地方

- **粉丝数一定要问**。没有锚点曲线就是错的。
- **日期是北京时间**。用户按本地时间记的发布日可能差一天，要在页脚说明。
- **标题是唯一的关联键**。导出表没有笔记 ID，标题必须和导出完全一致，一个字都不能改。
- **观看量低于 100 的不要硬解读**，直接写样本量不足。
- **高曝光低转粉要单独点出来**。这类笔记会把账号级指标全部拉花，还会污染兴趣标签，必须在建议里给止损规则。
- **改封面标题要重发，不是编辑**。编辑不会让笔记重新进流量池，这一条几乎每次都用得上。
