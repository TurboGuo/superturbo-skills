# 小红书涨粉诊断看板 · Skill

把小红书创作者后台的「笔记列表明细表」导出，变成一个可以直接打开的单文件 HTML
诊断看板：三项百分制评分、粉丝曲线、逐篇的算法与博主双视角诊断，以及 3 到 5 条
可执行建议。

任何人都能装上跑自己的账号，不需要任何账号授权、API key 或额外的连接器。

## 装上之后怎么用

把导出文件丢给 Claude，说「帮我做个小红书涨粉分析」就行。它会问你要粉丝总数和
时间范围，然后自己跑完整个流程。

## 你需要准备什么

**必须的，就这三样：**

1. **笔记列表明细表**：创作者中心 → 数据中心 → 笔记数据 → 导出。
   `.xlsx` 和另存的 `.csv` 都能读。
2. **今天的真实粉丝总数**：从主页上看一眼。导出表里没有粉丝时间序列，
   这是曲线唯一的锚点，推算不出来。
3. **时间范围**：默认最近 14 天，不足 8 篇就放宽到 30 天。

**可选，有了更好：**

- **封面图**。有图才能做真正的封面分析，没有就只能用点击率反推，看板会注明。
- **正文、主页截图、简介**。用于判断结构问题和关注转化。

文件已经存在电脑里某个文件夹？不用重新导，让脚本去找：

```bash
python3 scripts/discover.py <文件夹>
```

它按表头内容认文件而不是认文件名，改过名、下载了好几份都能找出来，
还会顺带报告可能的封面图目录。

## 依赖

```bash
pip install openpyxl          # 读 .xlsx 需要；用 .csv 则不需要
pip install pillow            # 可选，有封面图时用来做缩略图
```

没有 openpyxl 也能跑：把导出表另存为 `.csv`，脚本直接读。

## 看板包含什么

三项百分制评分（粉丝转化率、标题封面吸引力、内容吸引力）带良好中等较弱分档；
粉丝总数曲线加每篇涨粉量与三项得分，共用日期轴；逐篇分析可排序、分维度、
算法与博主双视角；3 到 5 条可执行建议。明暗两套配色，**全部离线可用**，
不联网、不加载外部字体、没有任何埋点。

## 关于数据准确性，请先读这段

- **小红书没有公开官方算法文档。** `references/` 里的机制与系数全部来自第三方
  运营分析与实测复盘，方向有多来源交叉印证，**具体数值是行业通行值而非官方口径**。
  每个参考文件都标了核对日期，并且 SKILL.md 要求 Claude **每次生成看板前重新搜一轮**，
  不直接信文件里的缓存数字。
- **列是按表头名读的，不是按位置。** 小红书改过导出表的列顺序；按下标读会读错列，
  而且结果看起来完全正常，是最难发现的一类错。表头名再变的话，往
  `scripts/prepare.py` 的 `ALIASES` 里加别名即可。
- **粉丝曲线**以「今天的真实粉丝数」为锚点倒推，总量准确，单日时点是近似。
- **导出表的首次发布时间是北京时间**，可能和你记忆中的发布日差一天。
- **观看量低于 100 的笔记**所有比率都不可靠，看板会写「样本量不足」而不是硬解读。

## 隐私

全部在本地跑。目录里没有任何脚本会联网，渲染出来的 HTML 没有外部资源、
没有埋点，`file://` 双击就能打开。

`assets/demo/` 里的示例数据完全是合成的，不是任何真实账号。
你生成的 `dashboard.html` **会**包含你的笔记标题和数据，那是你自己的私有文件。
脚本只把导出表的**文件名**写进页脚，不写完整路径，避免把你的目录结构带进交付物。

## 目录

```
SKILL.md                     主流程，八步
README.md                    本文件
references/
  algorithm.md               分发机制、四道闸门、CES 评分、各项基准线、核对日期与来源
  practitioner.md            博主实操经验基线，以及每次必须补搜的清单
  scoring.md                 三指标恒等式与百分制映射
  writing-guide.md           诊断与建议的写法规范
  format-contract.md         数字精度、前缀、条数上限等硬性格式约定
scripts/
  discover.py                在文件夹里找导出表和封面图
  prepare.py                 导出 → 指标（纯计算，按表头名读列）
  render.py                  指标 + 诊断 → 单文件 HTML
  verify.py                  交付前的机械校验
assets/
  template.html              看板模板，锁死全部样式与文案
  snippets.md                封面示意的 HTML 片段
  demo/                      一套完整的合成参照输出
```

## 为什么每次输出长得一样

- `assets/template.html` 锁死全部 CSS、布局、配色、明暗与交互
- 副标题、涨粉量卡片文案、页脚由 `prepare.py` 按数据自动生成
- 自由文本受 `references/format-contract.md` 约束
- `scripts/verify.py` 交付前机械校验 40 项
